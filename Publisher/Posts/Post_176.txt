<b>مرزبندی درست بین Taskها</b>
#Task_Decomposition(7/14)

تقسیم وظایف فقط به معنی بیشترکردن تعداد Taskها نیست. مرز مناسب جایی است که خروجی یک Agent یک artifact کامل و مستقل باشد و Agent بعدی بتواند بدون دانستن جزئیات داخلی مرحله قبل، کار خودش را انجام دهد. اگر Agent بعدی برای ادامه کار مجبور باشد بداند Agent قبلی چگونه به نتیجه رسیده، مرز ایجادشده احتمالاً مناسب نیست.

برای نمونه، استخراج مجموعه‌ای کامل از داده‌ها و تحویل آن به یک Agent تحلیل‌گر یک interface طبیعی ایجاد می‌کند. در مقابل، تقسیم یک پردازش واحد به دو نیمه‌ای که نتایجشان هم‌پوشانی دارند، Context بیشتری برای هماهنگی ایجاد می‌کند. Task Boundary مناسب باید implementation details مرحله قبلی را پنهان کند و یک Deliverable مشخص در اختیار مرحله بعد قرار دهد.
