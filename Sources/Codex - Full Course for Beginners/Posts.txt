#Codex (3/13)
<b>انتخاب Model متناسب با نوع کار</b>
همه درخواست‌ها به یک سطح از Reasoning نیاز ندارند. در Codex می‌توان بین سطوح مختلف Reasoning انتخاب کرد و این انتخاب مستقیماً روی زمان اجرای درخواست اثر می‌گذارد. هرچه سطح Reasoning بالاتر باشد، معمولاً پاسخ دقیق‌تر خواهد بود اما اجرای همان درخواست زمان بیشتری نیاز دارد. در مقابل، برای سؤال‌های کوتاه یا تغییرات کوچک، استفاده از سطح پایین‌تر باعث می‌شود پاسخ بسیار سریع‌تر آماده شود.

Modelهای سبک‌تر بیشتر برای کارهای سریع یا زمانی مناسب هستند که محدودیت مصرف وجود داشته باشد. همچنین امکان فعال کردن Fast Mode نیز وجود دارد تا اجرای درخواست‌ها با سرعت بیشتری انجام شود. ترکیب صحیح Model و Reasoning باعث می‌شود بین کیفیت خروجی و زمان اجرا تعادل مناسبی برقرار شود.

#Codex (7/13)
<b>مدیریت توسعه با Commandهای داخلی</b>
بخش مهمی از تعامل با Codex از طریق Commandهایی انجام می‌شود که با `/` آغاز می‌شوند. این Commandها فقط میانبر نیستند، بلکه هر کدام بخشی از مدیریت پروژه و Session را بر عهده دارند. برای مثال، `status/` وضعیت مصرف، محدودیت زمانی و میزان استفاده از Context را نمایش می‌دهد تا مشخص شود چه مقدار از ظرفیت فعلی باقی مانده است و چه زمانی لازم است وضعیت Session مدیریت شود.

با افزایش حجم مکالمه، Tool Callها و تغییرات پروژه، Context نیز بزرگ‌تر می‌شود و همین موضوع می‌تواند بر کیفیت پاسخ‌ها اثر بگذارد. برای همین `compact/` تمام اطلاعات مهم Session را در قالب یک خلاصه فشرده می‌کند و آن را به یک گفت‌وگوی جدید منتقل می‌کند تا Context دوباره فضای کافی در اختیار داشته باشد. همچنین امکان Fork کردن Chat، Pin کردن گفتگوها و ایجاد Chatهای جدید در همان Project نیز وجود دارد تا بتوان چند مسیر کاری مختلف را بدون از دست دادن ساختار پروژه مدیریت کرد.

#Codex (10/13)
<b>اجرای هم‌زمان Agentها با Worktree</b>
وقتی چند Agent به‌طور هم‌زمان روی یک Repository کار کنند، احتمال ایجاد تداخل بین تغییرات افزایش پیدا می‌کند. دلیل این موضوع آن است که همه Agentها روی فایل‌های مشترک تغییر ایجاد می‌کنند و همین مسئله می‌تواند باعث Conflict شود. Worktree برای حل همین مسئله به کار می‌رود.

در این ساختار، هر Agent روی یک نسخه مستقل از همان Repository فعالیت می‌کند. هر نسخه محیط کاری جداگانه‌ای دارد و تغییرات بدون تداخل انجام می‌شوند. پس از پایان توسعه، امکان ترکیب نتایج و مدیریت Merge نیز وجود خواهد داشت. Worktree بر پایه Git کار می‌کند و برای استفاده از آن باید ابتدا محیط مربوطه آماده شود. این قابلیت بیشتر در پروژه‌هایی کاربرد دارد که چند مسیر توسعه یا چند Agent به‌صورت موازی روی بخش‌های مختلف پروژه فعالیت می‌کنند.

#Codex (13/13)
<b>خودکارسازی کارهای تکراری با Scheduled Tasks</b>
همه فعالیت‌ها لازم نیست با اجرای دستی یک Chat آغاز شوند. Codex امکان تعریف Scheduled Task را فراهم می‌کند تا برخی وظایف در زمان مشخص و بدون نیاز به شروع دوباره توسط کاربر اجرا شوند. این قابلیت زمانی کاربرد دارد که یک فعالیت باید به‌صورت منظم تکرار شود یا اجرای آن به زمان خاصی وابسته باشد.

برای ایجاد چنین Taskهایی می‌توان آن‌ها را مستقیماً از طریق Chat ساخت یا از Templateهای آماده استفاده کرد. هنگام تعریف Task نیز امکان انتخاب Project، Chat یا Worktree، تعیین زمان اجرای تکرارشونده و انتخاب Model مورد استفاده وجود دارد. پس از تنظیم این موارد، Task به‌صورت خودکار در زمان مشخص اجرا خواهد شد، البته به شرط آنکه سیستم در دسترس باشد. این ساختار باعث می‌شود بسیاری از فعالیت‌های تکراری بدون نیاز به مداخله مداوم کاربر انجام شوند و فرایندهای روزانه یا دوره‌ای به شکل منظم اجرا شوند.
