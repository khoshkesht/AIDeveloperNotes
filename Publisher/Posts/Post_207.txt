#AI_Code_Review(0/10)

وقتی چند Agent هم‌زمان کد و تست می‌نویسند، وقت Code Review را کجا باید صرف کرد؟ تغییر یک Component مستقل و تغییر در زیرساختی که چند بخش برنامه به آن وابسته‌اند، عمق بررسی متفاوتی می‌خواهند. در این مجموعهٔ ۱۰ پستی، از همین تصمیم شروع می‌کنیم و می‌بینیم چطور با توجه به Blast Radius، شواهد داخل PR و امکان Rollback، تعیین کنیم کدام تغییر را باید دقیق بخوانیم.

در ادامه سراغ کارهای عملی می‌رویم. از Agent چه شواهدی بخواهیم تا نتیجه را بررسی کنیم؟ چطور Review را به یک Agent مستقل بسپاریم و کامنت‌های PR را در GitHub پیگیری کنیم؟ در پایان هم می‌بینیم بعد از Merge چه بررسی‌هایی برای Launch باقی می‌ماند و Feature Gate و Canary Deployment چطور به بررسی رفتار کد در Production کمک می‌کنند.
